# Flows

- `FlowsView` (with `FlowsModel`, `FlowWebView`): the Flows page, shown while `showFlows` (rail icon under Slack tasks, `AppModel.openFlows()`). The canvas fills the panel; a pill at its top left names the open flow and opens a floating flat list of flows (selection in UserDefaults `flowSelected`). The list has a "New flow" row (name alert; `FlowStore.create`) and, on row hover, rename and delete icons (delete asks first; `FlowStore.rename/delete`). There are no projects or sections, right a transparent `WKWebView` running React Flow (`App/Resources/flow.html/js/css`, built from `flow/` with `cd flow && npm install && npm run build`, bundle is committed like `marked.min.js`; `build-app.sh` copies it). Swift calls `window.sequenceFlow.load({flowId, graph})` / `.theme(mode)`; JS posts `ready` and `changed` (`{flowId, graph}`, the whole graph JSON, 400 ms after the last edit, flushed when another flow loads) to the `flow` message handler, saved verbatim by `FlowStore.saveGraph` (refuses anything without `nodes` and `edges` arrays; `FlowsModel.save`). Editable: a right-hand panel lists components (Start, Step, Task, End) to drag onto the canvas or click to add; drag from a node's dot to connect; selecting a step or connector shows an inspector (label, status, delete) and Delete/Backspace removes it. JS keeps what it last sent and ignores a load that equals it (so the 3 s poll does not clobber typing). Flows themselves (projects, sections, names) are still created by the MCP tools. Data polled every 3 s by `PRAGMA data_version`.
