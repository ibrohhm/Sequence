# MCP server

- `mcp/`: stdio MCP server for agents (TypeScript, own `package.json`): find, read, create and edit topics in the Sequence vaults by project and topic name, reading vaults from `vaults.json`. Every write is committed to the vault's git repo (a dirty target file is snapshot-committed first); a vault that is not a git repo is refused. `npm run build` and `npm test` inside `mcp/` (test builds first). Register: `claude mcp add --scope user sequence-vaults -- node ~/personal/sequence/mcp/dist/index.js`. Spec and plan: `docs/superpowers/specs/2026-11-15-vault-mcp-design.md`, `docs/superpowers/plans/2026-11-15-vault-mcp.md`. Also `list_slack_tags` (the tags the app edits), `get_slack_task` (one card by its number) and `upsert_slack_task` (required `tag`, returns the card's `number`): writes Slack thread cards (from the Workbench sync) into SQLite at `~/Library/Application Support/Sequence/slack-tasks.db` (env `SEQUENCE_SLACK_DB` overrides), keeping `status`/`archived`; the agent instructions are `mcp/skills/sync-slack-tasks/SKILL.md` (not active until linked as `~/.claude/skills/sync-slack-tasks`, which needs the user's approval). Spec and plan: `docs/superpowers/specs/2026-11-15-slack-tasks-design.md`, `docs/superpowers/plans/2026-11-15-slack-tasks-connector.md`. Flows tools `list_flows`, `get_flow`, `upsert_flow`, `delete_flow`: the single table `flows` (id, name unique, position, graph) lives in the Slack tasks DB, created with `IF NOT EXISTS` by both `FlowStore` (Swift) and `mcp/src/flows.ts` (identical DDL, parity test, no schema version bump); both also flatten a database from the version with `flow_projects`/`flow_sections` once on open (ids and graphs kept, a repeated name gets its old section in brackets); `upsert_flow` keeps a dragged position for nodes sent without `position`.
