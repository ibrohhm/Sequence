# Diagrams, web views and resources

- `DiagramWebView` backs both web views (`SVGView`, `MarkdownView`). A `contextmenu` script remembers the SVG under the cursor; the native menu then shows only Copy Image (the SVG is drawn to a 2x white-background canvas in JS and returned as PNG, so zoom, scroll and viewport size do not affect it; do not use `takeSnapshot`, its rect is in points while DOM rects are CSS px); WebKit's default items, such as Reload, are removed. Pinch zoom on diagrams is custom (`zoomsOnPinch`, sets `pageZoom` 0.2–4); WebKit's `allowsMagnification` snaps back to 1x.
- Markdown preview diagrams: each rendered diagram box shows an expand button (⤢) on hover that opens it in a full-panel overlay at its real size (scroll to pan); trackpad pinch zooms only the open overlay's diagram (0.2–4x around the cursor: `DiagramWebView.onPinch` calls JS `window.pinch`), never the markdown page itself; ✕ or Esc closes it, and an open overlay refreshes on re-render. Page code is `App/Resources/markdown.js` and `markdown.css`.
- `App/Resources`: `plantuml.jar` (bundled), `marked.min.js` (markdown parser), `markdown.js`/`markdown.css` (markdown preview page script and style), `diagram-context.js` (Copy Image script injected by `DiagramWebView`), `AppIcon.icns`, `PLANTUML_VERSION`. Web page code lives here as plain files, not Swift strings; Swift reads them with `AppResources.text(_:)` (bundle, or the source folder when run from source) and inlines them, so the markdown page's `<base href>` can still point at the vault. A new resource must also be added to the `cp` line in `build-app.sh`. `Theme.cssVariables` stays in Swift.
