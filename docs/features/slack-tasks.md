# Slack tasks

- `SlackTasksView` (with `SlackTasksModel`): the Slack tasks pages, shown in the detail panel while `showTasks` (the sidebar hides; opening a file or playground closes it). Pages: **Tasks** (every board tag) plus one page per list tag (Saved); the remembered page is UserDefaults `slackTagSelected` (`tasks` or a list tag id). Tasks shows each board tag as a collapsible section (header with chevron, name, count; collapsed tag ids in `slackTagsCollapsed`; sections sorted by tag name ignoring case), each with the four fixed columns Todo, In progress, Blocked, Done (the last counts as done; a card with another status shows in Todo); Settings > General "Group tasks by tag" (`groupTasksByTag`, default on) off shows one merged set of columns instead. Every task card shows its tag as a chip. Dragging a card only changes its status (in split mode only inside its own tag's section). The paste field adds to the tag chosen in the "Add to" menu (`slackAddTag`, default To-do) on Tasks, or to the list tag on a list page. One "Archived" list covers all board tags. Data is the SQLite database `~/Library/Application Support/Sequence/slack-tasks.db` (env `SEQUENCE_SLACK_DB`), schema v6 (v6 adds `tasks.reactions`, a JSON list of emoji names written by `upsert_slack_task`'s `reactions`): a `tags` table (id slug, name, kind board/list, slack_list none/todo/saved, reactions, columns, position, builtin) and `tasks` keyed by (tag, channel, thread); v5 normalises board statuses and board-tag columns to the four fixed ones. Built-in tags: To-do (Slack To-dos plus reactions `loading`/`loading1`, board) and Saved (Slack Saved, list); the rest are custom, reaction-fed, kind fixed at creation. Cards show channel, the agent's short summary (first message until one exists), a "→ next action" line (boards only), replies, "N new" since tagged and "quiet Nd" after 5 days; every card has a number (#12, one counter across all tags, assigned when the card is created by sync or by a pasted link; the next number is the highest plus one, so it is not reused as long as cards are archived rather than hard-deleted; a card an older build wrote without a number is numbered the next time any program opens the database) that an agent can use with the MCP tool `get_slack_task`; the card's "Open in Slack" button opens the thread (clicking the card itself does nothing), an Archive icon on the card (no context menu), the pointer is a hand over a card, paste a Slack link to add, "Archived" lists archived cards with a Jira-style status chip (Todo neutral, In progress blue, Blocked red, Done green; `Theme.statusColors`) and Restore. "Edit tags…" opens the **Slack tags window** (`SlackTagsEditorView`, a separate resizable `Window` scene: add, rename, reorder, delete tags and set emoji names; there is no column editor; deleting a custom tag hides its cards without deleting them). **Sync buttons** (refresh icon): each tag section header (split mode), the page header on a list page (that tag) and on a merged Tasks page (every board tag), and every card ("Sync this task"). They run `SlackSync` (`StudioCore`) = `claude -p` with the prompt on stdin (`tagPrompt`/`taskPrompt` tell it to use the sync-slack-tasks skill, the latter in its single task mode), `--allowedTools mcp__workbench__*,mcp__sequence-vaults__*,Skill`, `--disallowedTools mcp__claude_ai_Slack__*`, `--no-session-persistence`, temp cwd, 600 s timeout; the user's settings are loaded (the MCP servers and the skill live there). A spinner replaces the icon while it runs, and the last line of Claude's reply (or the error) shows as the notice. Claude is found via `ToolLocator.claude()`. Slack's own To-dos list is not known to be readable, so the sync skips it and the To-do tag is fed by its reactions. Look: pill tab control, tinted rounded column panels with a status icon and a count chip, a done card's title is struck through (also in the Archived list), rounded `cardBackground` tiles with chips (status in Jira colours on board cards, the emoji reactions the sync recorded for the card (`SlackEmoji` maps common names to glyphs, custom ones show as `:name:`), tag, replies neutral; "N new" and "quiet Nd" in the attention tint, always with a word), a footer of number, channel, age and the Open button, a hover border; no animation. Colours are `Theme` tokens (`columnBackground`, `cardBackground`, `cardBorder*`, `chip*`, `attention*`, `tabTrack`). Design intent and principles are in `PRODUCT.md`. The model polls `PRAGMA data_version` every 3 s while the board is open. Logic is in `StudioCore` (`SlackColumns`, `SlackTag`/`SlackTagRules`, `SlackTask`, `SlackBoard.sections/merged/groups`, `SlackLink`, `SlackTaskStore` over system SQLite3; both table DDLs must equal `SLACK_TAGS_DDL`/`SLACK_TASKS_DDL` in `mcp/src/slackdb.ts` and `SlackColumns.all` must equal `STANDARD_COLUMNS` there; tests in `mcp/` check both). Sequence writes tags, card status/archived and new cards for pasted links; the sync tool in `mcp/` owns the Slack facts and never writes tags.
