# Vault MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server that lets agents find, read, create and edit PlantUML and markdown topics in the user's Sequence vaults by project and topic name, with every write auto-committed to git.

**Architecture:** Small TypeScript modules, one responsibility each: vault registry, path safety, read-only finders, git layer, write operations, and a thin MCP wiring layer. Everything except the wiring is plain functions over the real filesystem and real git, tested in temp-directory vaults.

**Tech Stack:** Node v24, TypeScript (`tsc` to `dist/`), `@modelcontextprotocol/sdk`, `zod`, `node:test`, system `git`.

**Spec:** `docs/superpowers/specs/2026-11-15-vault-mcp-design.md`

## Global Constraints

- Code lives in `~/personal/sequence/mcp/` with its own `package.json`; no change to the Swift app.
- Vault list is read fresh on every call from `~/Library/Application Support/Sequence/vaults.json` (`{"vaults":[{"id","path","name"}]}`); env `SEQUENCE_VAULTS_FILE` overrides the path (tests).
- Allowed file types: `.puml .plantuml .pu .wsd .md`. Reject any path segment starting with `.`. Resolve with `realpath`; the target must stay inside the vault's real path.
- No delete, move or rename tool. No network transport. Stdio only.
- Git: the server never runs `git init`, never touches config or remotes, never uses `--no-verify`, adds no attribution trailer. A write to a vault that is not a git repo is refused. Commits stage and commit only the target file (`git add -- <file>`, `git commit -m <msg> -- <file>`).
- Commit messages: `mcp: <create|edit|overwrite> <vault-relative path>`; pending user changes to the target file first get `mcp: snapshot <vault-relative path> before edit`.
- `create_topic` fails if the file exists or the project folder is missing; `name` must include an allowed extension. `edit_topic` `old` must occur exactly once. `overwrite_topic` fails if the file does not exist. Writes are capped at 1 MB.
- Tools: `list_vaults`, `list_projects`, `find_topic`, `search_content`, `read_topic`, `create_project`, `create_topic`, `edit_topic`, `overwrite_topic`. All path-taking tools accept an optional `vault`; an ambiguous match returns candidates and acts on nothing.
- Repo rule from the user: nothing in this plan is committed in the Sequence repo unless the user asks. There are no commit steps; stop at each task's green tests.

## Review Focus

- File names with spaces, digits and dots, e.g. `0. qris meeting preparation with payment leads.md`: must be found, read, edited and committed (git pathspec quoting).
- `edit_topic` with an empty `old` string, or one that spans CRLF line endings: reject empty; match exactly as stored.
- Two tool calls writing in the same vault at once: serialize per vault so git never fails on `index.lock`.
- A symlink inside a vault pointing outside it, and a `..` path: refused.
- `vaults.json` missing, empty or malformed: a clear error from every tool, not a crash of the server.
- Target file ignored by the vault's `.gitignore`, or vault nested in a parent repo: the write still commits or reports clearly.

### Task 1: Scaffold, vault registry and path safety

**Files:**
- Create: `mcp/package.json`, `mcp/tsconfig.json`, `mcp/src/vaults.ts`, `mcp/src/paths.ts`, `mcp/src/errors.ts`
- Test: `mcp/test/vaults.test.ts`, `mcp/test/paths.test.ts`, `mcp/test/helpers.ts`

**Interfaces:**
- Produces:
  - `class VaultError extends Error` (`errors.ts`)
  - `type Vault = { id: string; name: string; path: string }`
  - `loadVaults(file?: string): Promise<Vault[]>`: default file from the constraints; throws `VaultError` on missing or malformed file.
  - `pickVault(vaults: Vault[], name?: string): Vault`: by case-insensitive name; no name and exactly one vault returns it; otherwise throws `VaultError` listing the vault names.
  - `const EXTENSIONS: string[]`
  - `resolveInVault(vault: Vault, input: string): Promise<{ abs: string; rel: string }>`: `input` is vault-relative or an absolute path inside the vault; enforces extension, dotfile and realpath rules; the file need not exist yet but its parent must resolve inside the vault.
  - `helpers.ts`: `makeVault(files: Record<string, string>, opts?: { git?: boolean }): Promise<Vault>` creating a temp dir (with `git init` and a baseline commit when `git` is true) and `vaultsFile(vaults: Vault[]): Promise<string>`.

### Task 2: Read-only tools (list, find, search, read)

**Files:**
- Create: `mcp/src/find.ts`
- Test: `mcp/test/find.test.ts`

**Interfaces:**
- Consumes: `Vault`, `pickVault`, `resolveInVault`, `EXTENSIONS`.
- Produces (`type Hit = { vault: string; project: string; path: string }`, `path` vault-relative):
  - `listProjects(vault: Vault): Promise<string[]>`: top-level non-hidden folders, sorted.
  - `findTopic(vaults: Vault[], query: string, opts?: { project?: string; vault?: string }): Promise<Hit[]>`: case-insensitive; every whitespace-separated query token must appear in the file name (extension ignored); `project` restricts to that folder (case-insensitive); more tokens matched earlier in the name ranks higher; at most 10.
  - `searchContent(vaults: Vault[], query: string, opts?: { project?: string; vault?: string }): Promise<(Hit & { line: string })[]>`: case-insensitive substring, first matching line per file, at most 20, allowed extensions only.
  - `readTopic(vaults: Vault[], input: string, vault?: string): Promise<string>`: uses `resolveInVault`; when no vault is given and the relative path exists in more than one vault, throws `VaultError` listing them.

### Task 3: Git layer

**Files:**
- Create: `mcp/src/git.ts`
- Test: `mcp/test/git.test.ts`

**Interfaces:**
- Consumes: `Vault`, `VaultError`, `makeVault`.
- Produces:
  - `isRepo(dir: string): Promise<boolean>`
  - `commitFile(vault: Vault, rel: string, message: string): Promise<{ committed: boolean }>`: stages and commits only that file via pathspec, using the repo toplevel (works when the vault is nested in a parent repo); `committed: false` when nothing changed.
  - `snapshotIfDirty(vault: Vault, rel: string): Promise<{ committed: boolean }>`: if the file has uncommitted or untracked changes, commits it with `mcp: snapshot <rel> before edit`.
  - `withVaultLock<T>(vault: Vault, fn: () => Promise<T>): Promise<T>`: serializes calls per vault path.

- [ ] **Step 1: Write failing tests** with real git in temp vaults: `isRepo` false for a plain dir, true after `makeVault(..., {git:true})`; `commitFile` after editing one of two modified files commits only that file (the other stays in `git status`); a file name with spaces and dots commits; `committed:false` when unchanged; `snapshotIfDirty` creates the snapshot commit only when dirty, and for an untracked file; two concurrent `withVaultLock` calls run one after the other (second starts after first ends); a vault in a subfolder of a parent repo commits into the parent repo.
- [ ] **Step 2: Run `npm test`.** Expected: FAIL.
- [ ] **Step 3: Implement `git.ts` with `child_process.execFile('git', args, { cwd })`** (never a shell string, so names with spaces are safe; use `git rev-parse --show-toplevel` for the repo root and `git status --porcelain -- <file>` for dirtiness).

### Task 4: Write tools

**Files:**
- Create: `mcp/src/write.ts`
- Test: `mcp/test/write.test.ts`

**Interfaces:**

- Produces (each returns `{ path: string; committed: boolean; snapshot: boolean }`; `snapshot` is true when a pre-edit snapshot commit was made; a commit failure after a successful write resolves with `commitError: string` instead of throwing):

  - `createTopic(vaults: Vault[], project: string, name: string, content: string, vault?: string)`
  - `editTopic(vaults: Vault[], input: string, old: string, replacement: string, vault?: string)`
