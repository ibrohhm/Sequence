# PlantUML Studio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS app that shows a folder of `.puml` files as a sidebar tree, renders the selected file, and offers a code-left / result-right playground with live preview.

**Architecture:** All logic lives in a local Swift package `StudioCore` (tool lookup, renderer, library scan/watch/operations, document session), tested from the CLI with `swift test`. A thin SwiftUI app target (generated by XcodeGen) wires `StudioCore` to views: sidebar, SVG viewer in `WKWebView`, and an `NSTextView`-based editor. Rendering uses one long-lived `java -jar plantuml.jar -pipe` child process.

**Tech Stack:** Swift 5.9+, SwiftUI, AppKit (`NSTextView`), WebKit (`WKWebView`), XCTest, XcodeGen, bundled PlantUML jar, Java and Graphviz from the host.

**Spec:** `docs/superpowers/specs/2026-10-30-plantuml-studio-design.md`

## Global Constraints

- macOS only, minimum macOS 14, Xcode project.
- Personal use only: no sandbox, no code signing or notarization, no App Store.
- PlantUML jar is bundled in the app. Java is NOT bundled; app requires it installed and shows a message naming the missing tool and the install command.
- Fully offline. Diagram content never leaves the machine. Remote includes (`!includeurl`, `!include http...`) are blocked; relative `!include` works, resolved against the open file's folder.
- Files stay plain `.puml` on disk. No database, no proprietary format.
- Sidebar shows `.puml`, `.plantuml`, `.pu`, `.wsd` files and folders containing them.
- Save is explicit (Cmd+S) with a dirty indicator. No autosave.
- A syntax or render error shows inline with the reason. Never a blank pane.
- Render target: under about 500 ms after the first render. Stale renders are cancelled when new input arrives.
- Tool lookup probes `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, plus a path override in settings (Finder-launched apps lack the shell PATH).
- Viewer renders SVG in `WKWebView`; export to PNG and SVG.
- Commits: the user's rule is never commit without their explicit request, and stage files by name (never `git add .`/`-A`). Every "Commit" step below runs only if the user has asked for commits; otherwise skip it and report that it was skipped.

## Review Focus

- A file with non-ASCII source (emoji, accented text): renders and saves without corruption.
- Two edits in quick succession: the older render never overwrites the newer result.
- `/usr/bin/java` exists as a macOS stub when no JDK is installed: must count as "Java missing", not as found.
- The open file is deleted or renamed externally: app shows a notice, keeps the editor text, never crashes.
- The remembered root folder no longer exists at launch: app falls back to the "choose a folder" state.
- A path containing spaces: opens, renders and saves.
- A source with no `@startuml`/`@enduml` or an empty file: shows an inline error or empty state, not a hang.
- Render with a `!includeurl http://...` line: blocked and reported, with no network request.

### Task 2: Renderer

**Files:**
- Create: `StudioCore/Sources/StudioCore/PlantUMLRenderer.swift`
- Test: `StudioCore/Tests/StudioCoreTests/PlantUMLRendererTests.swift` (tests use the jar at `App/Resources/plantuml.jar` and skip with `XCTSkip` if Java is not found)

**Interfaces:**
- Consumes: `ToolLocator.java()`, `ToolLocator.dot()` from Task 1.
- Produces:
  ```swift
  public enum RenderResult: Equatable { case svg(Data), failure(String), superseded }
  public actor PlantUMLRenderer {
      public init(javaURL: URL, jarURL: URL, dotURL: URL?)
      public func render(_ source: String, baseDirectory: URL) async -> RenderResult
      public func shutdown()
  }
  public func exportPNG(source: String, baseDirectory: URL) async -> Data?   // one-shot `-tpng` run, same security profile
  ```

- [ ] **Step 1: Write failing tests:**
  - `testRendersSimpleSequenceToSVG`: `@startuml\nA -> B: hi\n@enduml` → `.svg` whose text contains `<svg`.
  - `testSyntaxErrorReturnsFailureWithMessage`: invalid source → `.failure` with a non-empty message.
  - `testUnicodeSourceRenders`: participant named `"Pembayaran 💳 é"` → `.svg` containing that text.
  - `testSecondRenderIsFast`: after one warm-up, a second render completes in under 500 ms.
  - `testRelativeIncludeResolvesAgainstBaseDirectory`: temp dir with `part.puml`, main source `!include part.puml` → `.svg`.
  - `testRemoteIncludeIsBlocked`: source with `!includeurl http://127.0.0.1:9/x.puml` → `.failure` mentioning the include; no connection attempt (assert no listener received one).
  - `testCancelledRenderReturnsSuperseded`: start a render, cancel its `Task` immediately → `.superseded`; a following render still returns `.svg`.
  - `testChangingBaseDirectoryRestartsProcessAndStillRenders`.
- [ ] **Step 2:** Run `swift test --package-path StudioCore --filter PlantUMLRendererTests`. Expected: FAIL.
- [ ] **Step 3: Implement `PlantUMLRenderer`.** Keep one child process running `java -jar <jar> -pipe -tsvg -charset UTF-8 -pipedelimitor <unique marker>` with its working directory set to `baseDirectory` (restart the process when `baseDirectory` changes). Requests are serialized: write the source, read until the marker. When PlantUML output is an error image or stderr reports an error, return `.failure(message)`. Set `GRAPHVIZ_DOT` from `dotURL`. Set a PlantUML security profile that allows local relative includes and denies URLs (start with `PLANTUML_SECURITY_PROFILE=ALLOWLIST` with the base directory allowed; if that profile cannot satisfy both include tests, pick another profile and keep both tests green). On `Task.isCancelled`, drain and discard the in-flight output and return `.superseded`. Restart the process if it dies.
- [ ] **Step 4:** Run the same command. Expected: PASS.
- [ ] **Step 5: Commit** — `feat(renderer): persistent plantuml pipe renderer`.
