# Sequence

Personal Mac app (SwiftUI, no Xcode) to browse, view and edit PlantUML and markdown files. Not signed or notarized.

## Layout

- `Sources/StudioCore`: UI-free engine (renderer, scanner, watcher, file ops, `DocumentSession`, `MarkdownPreparer`, `TextSearch`).
- `App/`: SwiftUI + AppKit views, `AppModel` (all app state). Each window owns an `AppModel` (`WindowRoot` in `SequenceApp.swift`); menu commands reach the focused window's model through `focusedSceneObject`. Only the first window restores the last folder (`AppModel.claimRestore`).
  - `RootView`: window root. Picks setup, choose-folder or the workspace: the `IconRail` and two rounded, bordered panels (sidebar 180–480pt, default 236, drag the gap to resize (`SidebarResizer`, saved as `sidebarWidth`), detail) with an 8pt gap on the grey frame color. Layout follows the UI guideline from Pratik (see memory note `global/ui-guideline-from-pratik`). Holds app-wide alerts.
  - `IconRail` (in `ChromeButtons.swift`, with the shared `ChromeIconButton`): 52pt strip left of the panels. Files (toggles the sidebar, ⌘⌃S; leaves a playground), file search, PlantUML and Markdown playgrounds, Slack tasks (checklist icon, `AppModel.showTasks`/`openTasks()`), theme toggle and the gear (Settings window) at the bottom. There is no top bar.
  - `PageHeader`: header of the detail panel. File name with the folder as a muted subtitle; Copy name and Copy path icon buttons on the subtitle line, right after the folder (not in playgrounds); find-in-file (⌘F via the Edit menu command that replaces the system Find group: `AppModel.findQuery` sends a `FindRequest` that `CodeEditor` and `DiagramWebView` answer, `TextSearch` in `StudioCore` for editors; Return jumps to the next match); find collapses to a magnifier until opened (⌘F, or click); mode switch icons (Save has no button: ⌘S or File > Save, and a dot beside the name marks unsaved edits; a playground shows Save to folder… instead). Header icons use `tip: .aboveTrailing` so the hover label opens upward. Hover labels are not drawn by the icon: `ChromeIcon` publishes a `TipInfo` (`TipKey` preference) and `RootView` draws it with `TipOverlay` above the whole window, because the rounded panels clip anything that sticks out and later siblings paint over it. There is no native toolbar; do not add `.toolbar` items.
  - `SidebarView`: header (vault menu: vault list to switch, Manage Vaults…; New file and New folder icons), file search field (toggled by the rail's search icon, `AppModel.searching`/`query`), then the tree: folders and files as one tree of `TreeRow`s (folder icon + chevron, top-level folders start open, each level indents 20pt (`treeIndent`: chevron width plus gap) so files line up under their parent folder icon, guide line down each open folder), right-click menu (new file/folder, copy name/path, rename, delete). Drag a row onto a folder (or a file row, which means its parent folder, or the empty area, which means the vault root) to move it (`LibraryOperations.move`, `AppModel.move`; URLs from outside the vault are ignored, a folder cannot move into itself, an open file follows the move). Open/collapsed folders are saved per vault in UserDefaults `folderExpansion` (`FolderExpansion` in `StudioCore`); a saved choice beats the defaults (top-level folders open, ancestors of the selected file open). The sidebar has no hide button: the rail's Files icon (⌘⌃S) toggles it. New file/folder works like VS Code: `AppModel.beginNew` picks the target (`LibraryOperations.targetFolder`: focused folder, folder of a focused file, else the vault root; `sidebarFocus` is the last clicked row, cleared by clicking empty space), shows a `DraftRow` text field there, Return or blur creates it, an empty name drops it.
  - `SlackTasksView` (with `SlackTasksModel`): the Slack tasks pages, shown in the detail panel while `showTasks` (the sidebar hides; opening a file or playground closes it). Pages: **Tasks** (every board tag) plus one page per list tag (Saved); the remembered page is UserDefaults `slackTagSelected` (`tasks` or a list tag id). Tasks shows each board tag as a collapsible section (header with chevron, name, count; collapsed tag ids in `slackTagsCollapsed`; sections sorted by tag name ignoring case), each with the four fixed columns Todo, In progress, Blocked, Done (the last counts as done; a card with another status shows in Todo); Settings > General "Group tasks by tag" (`groupTasksByTag`, default on) off shows one merged set of columns instead. Every task card shows its tag as a chip. Dragging a card only changes its status (in split mode only inside its own tag's section). The paste field adds to the tag chosen in the "Add to" menu (`slackAddTag`, default To-do) on Tasks, or to the list tag on a list page. One "Archived" list covers all board tags. Data is the SQLite database `~/Library/Application Support/Sequence/slack-tasks.db` (env `SEQUENCE_SLACK_DB`), schema v6 (v6 adds `tasks.reactions`, a JSON list of emoji names written by `upsert_slack_task`'s `reactions`): a `tags` table (id slug, name, kind board/list, slack_list none/todo/saved, reactions, columns, position, builtin) and `tasks` keyed by (tag, channel, thread); v5 normalises board statuses and board-tag columns to the four fixed ones. Built-in tags: To-do (Slack To-dos plus reactions `loading`/`loading1`, board) and Saved (Slack Saved, list); the rest are custom, reaction-fed, kind fixed at creation. Cards show channel, the agent's short summary (first message until one exists), a "→ next action" line (boards only), replies, "N new" since tagged and "quiet Nd" after 5 days; every card has a number (#12, one counter across all tags, assigned when the card is created by sync or by a pasted link; the next number is the highest plus one, so it is not reused as long as cards are archived rather than hard-deleted; a card an older build wrote without a number is numbered the next time any program opens the database) that an agent can use with the MCP tool `get_slack_task`; the card's "Open in Slack" button opens the thread (clicking the card itself does nothing), an Archive icon on the card (no context menu), the pointer is a hand over a card, paste a Slack link to add, "Archived" lists archived cards with a Jira-style status chip (Todo neutral, In progress blue, Blocked red, Done green; `Theme.statusColors`) and Restore. "Edit tags…" opens the **Slack tags window** (`SlackTagsEditorView`, a separate resizable `Window` scene: add, rename, reorder, delete tags and set emoji names; there is no column editor; deleting a custom tag hides its cards without deleting them). **Sync buttons** (refresh icon): each tag section header (split mode), the page header on a list page (that tag) and on a merged Tasks page (every board tag), and every card ("Sync this task"). They run `SlackSync` (`StudioCore`) = `claude -p` with the prompt on stdin (`tagPrompt`/`taskPrompt` tell it to use the sync-slack-tasks skill, the latter in its single task mode), `--allowedTools mcp__workbench__*,mcp__sequence-vaults__*,Skill`, `--disallowedTools mcp__claude_ai_Slack__*`, `--no-session-persistence`, temp cwd, 600 s timeout; the user's settings are loaded (the MCP servers and the skill live there). A spinner replaces the icon while it runs, and the last line of Claude's reply (or the error) shows as the notice. Claude is found via `ToolLocator.claude()`. Slack's own To-dos list is not known to be readable, so the sync skips it and the To-do tag is fed by its reactions. Look: pill tab control, tinted rounded column panels with a status icon and a count chip, a done card's title is struck through (also in the Archived list), rounded `cardBackground` tiles with chips (status in Jira colours on board cards, the emoji reactions the sync recorded for the card (`SlackEmoji` maps common names to glyphs, custom ones show as `:name:`), tag, replies neutral; "N new" and "quiet Nd" in the attention tint, always with a word), a footer of number, channel, age and the Open button, a hover border; no animation. Colours are `Theme` tokens (`columnBackground`, `cardBackground`, `cardBorder*`, `chip*`, `attention*`, `tabTrack`). Design intent and principles are in `PRODUCT.md`. The model polls `PRAGMA data_version` every 3 s while the board is open. Logic is in `StudioCore` (`SlackColumns`, `SlackTag`/`SlackTagRules`, `SlackTask`, `SlackBoard.sections/merged/groups`, `SlackLink`, `SlackTaskStore` over system SQLite3; both table DDLs must equal `SLACK_TAGS_DDL`/`SLACK_TASKS_DDL` in `mcp/src/slackdb.ts` and `SlackColumns.all` must equal `STANDARD_COLUMNS` there; tests in `mcp/` check both). Sequence writes tags, card status/archived and new cards for pasted links; the sync tool in `mcp/` owns the Slack facts and never writes tags.
  - `FlowsView` (with `FlowsModel`, `FlowWebView`): the Flows page, shown while `showFlows` (rail icon under Slack tasks, `AppModel.openFlows()`). The canvas fills the panel; a pill at its top left names the open flow and opens a floating flat list of flows (selection in UserDefaults `flowSelected`). The list has a "New flow" row (name alert; `FlowStore.create`) and, on row hover, rename and delete icons (delete asks first; `FlowStore.rename/delete`). There are no projects or sections, right a transparent `WKWebView` running React Flow (`App/Resources/flow.html/js/css`, built from `flow/` with `cd flow && npm install && npm run build`, bundle is committed like `marked.min.js`; `build-app.sh` copies it). Swift calls `window.sequenceFlow.load({flowId, graph})` / `.theme(mode)`; JS posts `ready` and `changed` (`{flowId, graph}`, the whole graph JSON, 400 ms after the last edit, flushed when another flow loads) to the `flow` message handler, saved verbatim by `FlowStore.saveGraph` (refuses anything without `nodes` and `edges` arrays; `FlowsModel.save`). Editable: a right-hand panel lists components (Start, Step, Task, End) to drag onto the canvas or click to add; drag from a node's dot to connect; selecting a step or connector shows an inspector (label, status, delete) and Delete/Backspace removes it. JS keeps what it last sent and ignores a load that equals it (so the 3 s poll does not clobber typing). Flows themselves (projects, sections, names) are still created by the MCP tools. Data polled every 3 s by `PRAGMA data_version`.
  - `MainView`: detail pane for the open file. Owns the title, mode picker, Save button and the mode switch (view / edit / editPreview).
- Vaults: a vault is a named folder (`Vault`/`VaultList` in `StudioCore`, JSON at Application Support/Sequence/vaults.json; the list is reloaded before each change so windows share it). `AppModel.openRoot` registers any opened folder as a vault; `switchVault`, `createVault` (makes a folder in ~/Documents/Sequence), remove (forgets only, files stay) and rename (display name only) go through `VaultStore.update`. `VaultStore.shared` holds the list for every window; `AppModel.active` (set when a window becomes key, `WindowActivation`) is the window the Settings window acts on. `VaultsView` is the Vaults tab of the Settings window (`SettingsView`, ⌘, and the rail gear: General = theme icon buttons (sun/moon), sidebar "Show folder icons" / "Show file icons" toggles (`showFolderIcons`, `showFileIcons`, read by `TreeRow` and `DraftRow`) and the "Show AI editor" toggle (`aiEditorEnabled`, hides `PromptBar` and ⌘K), Vaults, About = version, PlantUML and Java in use (no Claude row)). The sidebar vault menu, File > Manage Vaults… and the choose-folder screen open it with `openSettings(tab: .vaults)` (`OpenSettingsAction` extension in `SettingsView.swift`; the AppKit `showSettingsWindow:` action did nothing). The theme is stored in UserDefaults `theme`; each window's `AppModel` follows changes made there. All three tabs use a grouped `Form` and the window is a fixed 480x480 so switching tabs does not resize it. The vault actions are disabled with a hint when no app window is open (`VaultStore.hasWindow`, cleared by `windowClosed`). Dialogs are native windows or alerts, never in-window sheets; system alerts (rename, delete, unsaved changes) stay as alerts.
- Playground: scratch files live in Application Support (`Playground` in `StudioCore`), one for PlantUML and one for markdown. `AppModel.inPlayground` is true when the open session is one of them; it hides the sidebar (the rail's Files button calls `closePlayground()`), forces Edit with preview, autosaves on typing, and swaps the top bar controls for Save to folder. The two playgrounds are separate entries in the sidebar header menu and the File menu (⌘⇧P, ⌘⇧M), and the empty "Select a file" state (`PlaygroundChoices` in `RootView`: rows styled like sidebar rows, also on the choose-folder screen); there is no language switch.
- Markdown formatting: the Format menu (⌘B bold, ⌘I italic) calls `AppModel.format`, which sends a `MarkdownFormat` to `CodeEditor`; `MarkdownFormatter` (`StudioCore`) computes the edit (wrap, unwrap, bold+italic combos, spaces kept outside the markers) and the editor applies it through `shouldChangeText` so undo works. Only for markdown files with the editor visible.
- AI prompt: `PromptBar` (bottom of the detail panel; ⌘K via the Ask menu focuses it) calls `AppModel.askAI`, which runs `AIEditor` (`StudioCore`) = `claude -p` with a fixed system prompt per `DocumentKind` (`AIEditor.systemPrompt`), the document and instruction on stdin, `--tools ""`, `--setting-sources ""`, `--disable-slash-commands`, `--no-session-persistence`, temp cwd and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` so the user's hooks and CLAUDE.md cannot leak into the reply (`--bare` is not used: it blocks OAuth login). The reply replaces the whole text; the old text is kept for Undo, and a result is dropped if the file changed meanwhile. Claude is found via `ToolLocator.claude()` in `claudeDirs`. Edit the system prompts to change what Claude may do.
- `DiagramWebView` backs both web views (`SVGView`, `MarkdownView`). A `contextmenu` script remembers the SVG under the cursor; the native menu then shows only Copy Image (the SVG is drawn to a 2x white-background canvas in JS and returned as PNG, so zoom, scroll and viewport size do not affect it; do not use `takeSnapshot`, its rect is in points while DOM rects are CSS px); WebKit's default items, such as Reload, are removed. Pinch zoom on diagrams is custom (`zoomsOnPinch`, sets `pageZoom` 0.2–4); WebKit's `allowsMagnification` snaps back to 1x.
- Markdown preview diagrams: each rendered diagram box shows an expand button (⤢) on hover that opens it in a full-panel overlay at its real size (scroll to pan); trackpad pinch zooms only the open overlay's diagram (0.2–4x around the cursor: `DiagramWebView.onPinch` calls JS `window.pinch`), never the markdown page itself; ✕ or Esc closes it, and an open overlay refreshes on re-render. All in the page JS/CSS of `MarkdownView`.
- `App/Resources`: `plantuml.jar` (bundled), `marked.min.js` (markdown parser), `AppIcon.icns`, `PLANTUML_VERSION`.
- `Tests/StudioCoreTests`: Swift Testing suites.
- `mcp/`: stdio MCP server for agents (TypeScript, own `package.json`): find, read, create and edit topics in the Sequence vaults by project and topic name, reading vaults from `vaults.json`. Every write is committed to the vault's git repo (a dirty target file is snapshot-committed first); a vault that is not a git repo is refused. `npm run build` and `npm test` inside `mcp/` (test builds first). Register: `claude mcp add --scope user sequence-vaults -- node ~/personal/sequence/mcp/dist/index.js`. Spec and plan: `docs/superpowers/specs/2026-11-15-vault-mcp-design.md`, `docs/superpowers/plans/2026-11-15-vault-mcp.md`. Also `list_slack_tags` (the tags the app edits), `get_slack_task` (one card by its number) and `upsert_slack_task` (required `tag`, returns the card's `number`): writes Slack thread cards (from the Workbench sync) into SQLite at `~/Library/Application Support/Sequence/slack-tasks.db` (env `SEQUENCE_SLACK_DB` overrides), keeping `status`/`archived`; the agent instructions are `mcp/skills/sync-slack-tasks/SKILL.md` (not active until linked as `~/.claude/skills/sync-slack-tasks`, which needs the user's approval). Spec and plan: `docs/superpowers/specs/2026-11-15-slack-tasks-design.md`, `docs/superpowers/plans/2026-11-15-slack-tasks-connector.md`. Flows tools `list_flows`, `get_flow`, `upsert_flow`, `delete_flow`: the single table `flows` (id, name unique, position, graph) lives in the Slack tasks DB, created with `IF NOT EXISTS` by both `FlowStore` (Swift) and `mcp/src/flows.ts` (identical DDL, parity test, no schema version bump); both also flatten a database from the version with `flow_projects`/`flow_sections` once on open (ids and graphs kept, a repeated name gets its old section in brackets); `upsert_flow` keeps a dragged position for nodes sent without `position`.
- `docs/superpowers/`: design spec and plan.

## Commands

- `./test.sh`: run tests. Only Command Line Tools are installed (macOS too old for Xcode), so tests use Swift Testing with CLT framework flags. Do not use `swift test` directly or XCTest.
- `./build-app.sh`: build `build/Sequence.app`. Quit the running app (⌘Q) first, or reopening shows the old build.
- After every app change: quit the running app (`osascript -e 'quit app "Sequence"'`, wait until it exits), run `./build-app.sh`, then `open build/Sequence.app`.
- Run `./test.sh` before every commit.
- Version: the `VERSION` file (semver `major.minor.patch`) is the single source; `build-app.sh` writes it into Info.plist and About shows it. Every commit that changes the app bumps it in that same commit, by commit type: `feat` = minor (patch resets to 0), `fix`/`refactor`/`perf` = patch, a breaking change (removed shortcut, changed file or settings format) = major (minor and patch reset). `docs`/`test`/`chore`/`build`/`ci` do not bump. Say the new version in the commit report.

## Rules

- Logic goes in `StudioCore` with a test written first. Views in `App/` are not unit tested.
- A trimmed Java runtime is bundled at `Contents/Resources/jre` (`build-app.sh` jlinks it from the installed JDK into `build/jre`, cached; delete `build/jre` to rebuild it) and `ToolLocator.bundledDirs` searches it first, then Homebrew and system dirs. It matches the build machine's architecture (this toolchain runs as x86_64 under Rosetta, so the app is x86_64; Apple Silicon Macs run it through Rosetta). The app is ad-hoc codesigned. Graphviz is not bundled and is optional: PlantUML falls back to Smetana.
- Renderer is one long-lived `java -pipe` process, serialized in the `PlantUMLRenderer` actor. Do not add concurrent renders on it.
- Remote includes and URLs are blocked in diagram source. Keep the `analyze` pre-scan and `PLANTUML_SECURITY_PROFILE=LEGACY` together.
- Markdown preview escapes raw HTML. Keep it that way; the page can read local files.
- Supported files: `.puml .plantuml .pu .wsd` (diagrams), `.md` (markdown). `.mdx` is out of scope. A folder shows in the tree when it holds supported files or is empty (so a new folder does not vanish); folders holding only other files are hidden.
- Theme (light/dark) is `AppModel.theme`, saved in UserDefaults, overrides macOS via `.preferredColorScheme`. All theme colors (frame, panel, border, orange accent, editor, sidebar rows, syntax, web CSS variables keyed by `data-theme`) live in `App/Theme.swift`. Dark follows VS Code "Dark Modern". Do not hardcode hex in `SVGView` or `MarkdownView`.
- `WindowConfigurator` makes the title bar transparent in the frame color and removes the full-size content view so content never slides under it when the window resizes or the sidebar toggles.
- Layout is plain stacks (`HStack` of fixed-width panels), not `NavigationSplitView`: on macOS 26 the latter draws the sidebar as a floating glass panel that cannot be turned off. Sidebar is a custom tree, not `List`, so hover and selection styling stay controllable. Do not switch back.
- Can't screenshot the UI here. Say when UI changes are unverified.
- After every change, update this file if features, layout, commands or rules changed. Commit it with the change.

## Git

- Commit format `<type>(<scope>): <subject>`, lowercase imperative.
- Stage files by name. No `git add .` or `-A`. No `Co-Authored-By`.
- Commit only when asked.
